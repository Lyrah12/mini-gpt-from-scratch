# 模型质量诊断记录

检查日期：2026-11-04。针对已完成的约 0.05B GPT，检查实现、数据、训练记录和实际输出。本轮未更新模型权重、训练配置或原始实验结果，未重新训练，也未在本地编译 PDF。

## 结论

没有发现本次核查范围内的致命实现错误。效果有限与训练预算有关，同时发现了值得优先处理的**输入信息缺失**：XL-Sum 的 `summary` 字段承载了部分新闻导语，但当前任务仅使用 `text` 生成 `title`。部分参考标题的重要数字或事件描述因此不在输入中。直接扩大模型或增加生成随机性无法补回这些信息。

建议保留现有实验作对照，先审查数据构造，再决定是否进行小规模、独立命名的后续实验。加上 `summary` 会改变任务输入，必须单独说明、重新准备数据和训练评测；不能把新分数当作相同输入下纯模型优化的结果。

## 已核对的实现和实物数据

- 重新执行模型和数据相关测试：**7 项通过**，耗时 17.55 秒。检查因果遮罩、手写与 SDPA 注意力的前向/梯度一致性、共享权重、小任务过拟合、BPE 往返、标题损失遮罩及 ROUGE。
- 数据清单中 9 个文件的 SHA-256 及 tokenizer SHA-256 全部匹配。当前 `minigpt` 源码和三组训练记录中的源码指纹一致。
- 对全部 **46,009** 条已处理记录检查 tokenizer 往返和字面特殊 token：异常均为 0。
- 逐条重建训练/验证的 **41,347** 条 SFT 编码，与实际 `.npy` 完全一致；重建两份预训练 token 流的哈希，与实际 `.bin` 一致。
- 三个分区之间，文档 ID、规范化正文哈希及前 256 个规范化字符分组均无交集。这不证明所有相似报道或同事件报道都已消除。
- 标题标签采用下一 token 移位，首个标题 token 由提示末尾位置预测；提示和右侧 padding 的标签为 -100。因果注意力使右侧 padding 不影响前面的有效位置，不需要将缺少 padding attention mask 误判为当前损失计算错误。
- 梯度累积按整个有效批量的标题 token 数加权；训练和生成使用相同提示构造及正文预算。
- 重新计算 8 组评测的逐条/平均 ROUGE，与记录一致；每个分区内四种方法的评测样本 ID 列表相同。
- 在原 RTX 4060、BF16 设置下重放按 ID 排序的前 8 条验证标题：**8/8 逐字一致，且全部正常生成 EOS**。

## 输入缺失与截断

512-token 上下文中，提示前缀占 23 token、后缀占 5 token、BOS 占 1 token，标题预留 64 token，所以正文实际只保留前 **419 token**。

| 分区 | 记录数 | 正文被截断 | 标题被截断 |
|---|---:|---:|---:|
| train | 36,762 | 21,017（57.17%） | 0 |
| val | 4,585 | 2,551（55.64%） | 0 |
| test | 4,662 | 2,619（56.18%） | 0 |

“被截断”仅表示正文超过预算，不等于这条样本的必要信息一定被删掉；全部参考标题都未触及 63-token 的目标截断上限。

回查原始 XL-Sum 压缩包，精确按正文哈希匹配固定验证集 200 条记录，其中 **198/200** 的 `summary` 未完整出现在 `text` 中。这不能理解为其中 198 条都无法完成标题任务，也不意味着将 `summary` 拼入正文一定提升生成质量。

两个可核验的例子：

- `01265c776a59…`：参考标题是“法国扣押12名巴黎袭击嫌疑犯”。原始 `summary` 明确写了扣押 12 名嫌疑犯；`text` 中的 12 人指袭击遇难者。模型输出“法国警方逮捕7名枪手”，数字和人物身份都不可靠。
- `011ca71205b1…`：参考标题是“英限制‘过分色情’商品广告播出时间”。禁止在晚间 7 点半前播出的具体规定在 `summary` 中，当前正文主要叙述广告内容和投诉。

以参考标题字符在输入中的多重集召回作词面诊断，固定验证集的可见输入均值为 **83.85%**；假设将导语放在正文前、仍保持 419-token 预算，则为 **88.61%**。这只是输入字符覆盖度，不是模型分数、语义证据覆盖率或预期性能提升。

数据来源：[XL-Sum](https://huggingface.co/datasets/csebuetnlp/xlsum)，版本 `30fece425f9a3866e04321773ca7a80056d55ca6`，许可 CC-BY-NC-SA-4.0。本轮未对现有数据进行任何改写。

## 模型确实使用正文，但仍会生成错误

在固定的 200 条验证样本上，对相同参考标题计算 teacher-forcing token 平均交叉熵：

| 输入 | 交叉熵 |
|---|---:|
| 正确新闻正文 | 3.9404 |
| 循环错配到下一条新闻的正文 | 6.6710 |

两种情况均计入 2,332 个标题目标 token。正文错配明显影响预测，支持模型利用了正文信息；该操作也可能改变提示长度与位置，因此不能单凭此实验证明语义理解或事实可靠性。这里使用纯 BF16 权重和 float32 交叉熵，训练日志采用 float32 权重与 BF16 autocast，数值不可要求逐位相同。

对固定前 8 条验证样例的人工核查还发现：

- 重复和泛化标题，如“海外生存之惑:海外生存之惑”。
- 事件时间关系错误：正文和参考说陈云林会后离台，输出变为“两会前陈云林访台”。
- 人物关系混淆：有关吴花燕及其弟弟的报道，被生成为把吴花燕放在弟弟位置的标题。
- 事实主体和确定性错误：正文说经济学界预期央行可能出台措施，生成标题却称“英国央行宣布”。

这些是用于定位问题的个案分析，不是随机人工标注得到的总体错误率。现有测试集主方法的空输出 0 条、原文连续四字符片段至少出现三次 17 条、数字未直接出现在完整正文中 9 条，均与原报告核对一致；启发式标记不是事实错误率。原文和去标点后的重复筛查分别存储，二者不能混用。

## 训练量和生成接口

- 预训练累计 98,304,000 token，原始训练流 26,312,816 token，累计量约为原始流的 3.74 倍；随机有放回窗口采样不等于顺序完成 3.74 个 epoch。
- SFT 1500 步、有效批量 32，共抽取 48,000 条样例。按实际种子重建采样序列，覆盖训练集中约 **73.05%** 的不同文档；有放回采样使部分记录未被抽中。这是预算与采样方式的取舍，不是数据加载失败。
- 三组最佳验证损失均位于最后一个检查点。预训练最后 500 步从 4.8495 降至 4.7993，主方法 SFT 从 4.0307 降至 3.9666。尚无明显的后期验证恶化，但改善减慢，不能推断延长多少步能带来多少生成收益。
- 训练过程中的 SFT 损失只用固定抽样的 80 条有放回验证记录估计；生成评测另用固定 200 条验证样本。后续选择训练长度前，宜扩大验证损失覆盖，避免过度依赖小子集。
- 标题生成使用贪心解码，没有重复惩罚。`minigpt.generate` 的 `--task title` 当前固定 64-token 上限及 temperature=0，命令行的 `--temperature` 和 `--max-new-tokens` 只影响续写模式。比较标题解码策略前，需要显式扩展接口并在验证集上选择。

## 后续优先级

1. 先决定是否把原始导语纳入新闻输入，或保留 text-only 任务但筛查输入无法支持的目标；前者需要明确记录输入变化，后者也会改变数据分布。两者都不能仅为提高测试分数而选择样本。
2. 在固定验证集上，小范围比较去重复解码等设置，观察事实错误和 ROUGE 的取舍；解码规则不能补回输入之外的证据，也不保证修复人物关系。
3. 若数据方案确定，再做独立命名的补训/重训实验。当前不建议直接增加参数量。继续使用原词表可兼容现有权重；重新学习词表不能直接沿用旧 checkpoint。
4. 保留这次原始权重、预测和测试结果。后续调参依据验证集；原测试结果已被检查，反复用其决定方案后，不应再宣称该测试是完全未接触的最终选择依据。
