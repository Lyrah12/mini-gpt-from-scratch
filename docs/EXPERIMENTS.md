# 实验方案与记录规则

## 研究问题

1. 随机初始化的小型 GPT 能否通过新闻语料学习中文续写规律？
2. 标题生成 SFT 是否改善模型按指令生成标题的能力？
3. 在相同微调配置下，预训练初始化与随机初始化有什么差异？

## 数据和隔离

- 使用作者发布的 `news2016zh`，含正文和标题。当前实验属于**中文新闻领域语言建模**，不声称覆盖通用中文任务。
- 清洗 HTML、控制字符、空白，并做 NFKC 规范化；保留正文长度 100～10000 字符、中文字符比例至少 50%、标题 4～80 字符的样本。
- 若正文以完整标题开头，去除该标题。随后按移除标点与空白后的正文哈希、前 256 个规范化字符哈希去重。该启发式方法不能保证移除全部改写转载或同一事件报道。
- 扫描所有提供文件，蓄水池抽样最多 300000 条合格唯一记录；种子 42。按前缀哈希和种子确定约 96%/2%/2% 的划分，实际数量以 manifest 为准。
- 原始 train/valid 文件共同构成原始池，本文重建划分，不与原数据集官方榜单分数直接比较。
- BPE 只从本文 train 部分训练；val/test 不参与分词器学习、预训练或 SFT。预训练与 SFT 可以使用同一训练新闻，因为评估始终隔离；报告明确这是同领域迁移。

## 初始配置

| 项目 | 预训练 | 预训练后 SFT | 随机初始化 SFT |
|---|---:|---:|---:|
| 随机种子 | 42 | 42 | 42 |
| 优化器步数 | 3000 | 1500 | 1500 |
| 微批量 | 8 | 8 | 8 |
| 梯度累积 | 8 | 4 | 4 |
| 最大学习率 | 3e-4 | 5e-5 | 5e-5 |
| 预热步数 | 100 | 50 | 50 |
| 权重衰减 | 0.1 | 0.01 | 0.01 |
| 梯度裁剪 | 1.0 | 1.0 | 1.0 |
| 计算精度 | BF16（支持时） | 同左 | 同左 |

三组均为 8 层、10 头、640 维隐藏层、MLP 扩张 4 倍、学习式绝对位置编码、Pre-LN、GELU、dropout 0.1、输入输出词嵌入共享。优化器 AdamW，beta=(0.9,0.95)，预热后余弦衰减至最大学习率的 10%。

这是**试跑前的配置**。总预训练输入预算为 98,304,000 token（有放回随机窗口），不是独立语料 token 数；SFT 各抽样 48000 条次（有放回），不等于完整遍历数据集一个 epoch。SFT 输入计数包含填充，同时另记有效标题目标 token 数。必要时根据验证曲线增加训练预算，并同步修改配置和报告。修改配置后使用新输出目录，不能在已有 checkpoint 上偷偷改变调度。

## 评测组与选择规则

| 方法 | 用途 |
|---|---|
| 首句前 32 字符 | 低成本抽取基线；使用与模型相同的可见正文前缀 |
| 仅预训练 | 观察无标题指令微调时的任务表现 |
| 预训练后 SFT | 主方法 |
| 随机初始化 SFT | 与主方法只改变初始化，其余微调配置相同 |

随机初始化对照使用同一 SFT 学习率，是控制变量比较，不代表该对照已单独调参到最优；预训练组额外消耗预训练算力，也不是等总算力比较。若增加调参实验，只在验证集进行并保留独立配置和日志。

每 100 步在固定随机窗口/样例上计算验证损失，按有效目标 token 汇总，选取最低损失的 `best.pt`。默认验证是 20 个批次的固定抽样估计，不是整份验证集平均。SFT 的条件困惑度只统计标题 token，不能与预训练困惑度直接比较。

先评测固定验证子集 200 条作诊断；冻结配置与解码参数后，在固定测试子集 500 条做最终比较。子集由独立 RNG 做蓄水池抽样，四组必须共享 selection_hash。实际 n 不超过可用样本数。贪心解码、最多 64 个新 token（含 EOS），不按测试结果修改训练或挑选检查点。

## 中文指标定义

逐字符保留 Unicode 字母与数字，英文小写化，移除空白与标点。ROUGE-1/2 为字符 n-gram 重合的 F1，ROUGE-L 为最长公共子序列 F1，各样本宏平均。空预测记 0，不用英文分词器处理中文。此定义与其他工具的默认分词结果可能不同，不能直接跨实现比较分数。

保存所有预测、参考标题、正文和逐条分数，另记空输出率。人工分析关注事实一致性、实体与数字、重复和过长标题。固定展示按哈希排序前四条，同时可另外讨论失败案例并说明挑选规则。ROUGE 只能衡量词面重合，单种子单次实验不宣称统计显著性。

## 原始证据

- `data/processed/manifest.json`：来源、原始文件哈希、清洗、去重、划分及 token 数。
- `runs/cloud/*/run.json`：配置、实际参数量、环境、初始权重来源和数据指纹。
- `metrics.jsonl`：训练/验证损失、学习率、梯度范数、速度、token 数与显存。
- `status.json`：实际训练步数和是否完成；`best.pt/last.pt/initial.pt`：检查点。
- `resume_step_*.json`：恢复时使用的环境记录。
- `eval_test_*/`：固定测试子集分数与逐条预测。
- `continuations.json`：固定提示词在随机初始化和预训练后的实际续写。
- `report/generated/`：验证来源一致性后生成的表格、曲线和汇总 JSON。

最终结论由这些记录得出。若结果不理想，报告说明欠训练、截断或模型容量等可能原因，并用追加实验检验，不把猜测写成已经证实的原因。
